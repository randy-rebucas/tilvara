### What held up
**Database**
- 134 migrations on disk, all in the journal and all applied on dev. `when` only increases.
- No table has RLS enabled without FORCE. No `tenant_id` table lacks RLS.
- Every SECURITY DEFINER function has `search_path`. None is executable by PUBLIC. `onepos_app` executes only the intended `billing_*`, `auth_public_shop*` and hand-off functions, and `onepos_worker` only the tick.
- `BUSINESS_GAUGES` equals `platform_metrics()` (15 rows). The three billing alerts have one-line `expr` and existing anchors.

**Billing**
- Exact-amount settlement; replay dedup by event id and reference.
- The webhook is signed over the raw bytes, with a 300 s window and `timingSafeEqual`. The return redirect never pays.
- Receipts are numbered without gaps under an advisory lock. VAT is `round(amount×12/112,2)`, with a CHECK.
- Bills change status only; payments and receipts are append-only.
- The BFF allow-list for billing is pinned to UUIDs.

**Session 42 fixes**
- The proxy refuses encoded or dot segments.
- Hand-off sessions are bound to their business and parent session.
- `onepos_readonly` is NOLOGIN.

**Session 43–44 diffs**
- No open redirect (`shopAddress` requires `isSubdomainSlug`).
- The raw body is used only on the webhook path.

**Counter**
- Server and offline engine price alike (`applyPromotions`, `calculateTax`, `knownAt`).
- Header totals equal Σ lines + Σ charges (DB CHECKs).
- Idempotency: the key is claimed in the same transaction and the hash covers user, route and body. The till keeps the key on an unknown outcome.
- Returns are locked per sale and limited to what remains. The store-credit share goes back to the payer.
- Price overrides are single-use.
- BLOCK stock checks lock in sorted order.

**Books**
- Every stock and books document traced posts exactly one balanced entry in the same transaction and requires an Idempotency-Key.
- Movements are sorted by variant. The costing and lot triggers behave as ADR-0012 and ADR-0020 say.
- On dev, Inventory GL = Σ `stock_balances.value` per entity.

**Wiring**
- 301 routes = 301 OpenAPI operations.
- 135 admin client URLs, 236 admin server paths and 45 POS calls all map to real routes and methods.
- Request body keys match the zod schemas.
- Copy keys: admin EN/FIL 2601/2601, POS 372/372, none unused.
- `TOPIC_BY_PATH` covers every page, and every quoted guide label exists.
- No `.only`, `.skip`, TODO or FIXME. Only deliberate history is left from the removed trades.
