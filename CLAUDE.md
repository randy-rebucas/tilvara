# Tilvara — guidance for Claude sessions

**Start every session by reading `docs/STATUS.md`** (current phase, what's verified, next task), then `docs/BACKLOG.md` (the plan) and `docs/LEFTOVER.md` (open items left by finished slices). Open items of the second full audit, ready to work on: `docs/OPEN-ITEMS-2026-10-27.md`. The full product spec is `docs/SPEC.md` (copy of the user's master prompt) — it is the source of truth for requirements.

## Working rules (from the spec)
- Work phase by phase (Inspect → Plan → Implement → Validate → Review → Document → Report). Don't start a later phase while an earlier phase has open critical defects.
- A feature is done only when schema, domain rules, API, authorization, failure handling, and automated tests all work. Never report UI-only or mocked work as complete; name dev adapters `Dev*`/`Fake*`.
- Never claim tests passed unless they were run in this session; quote the command.
- Never claim BIR accreditation/compliance. Production invoice issuance stays disabled until the compliance gate in `docs/compliance/` is cleared.
- Money/quantities: `@1pos/money` only, decimal strings on the wire, never JS numbers.
- New tenant tables are policed automatically: `rls-catalog.test.ts` (schema rules) and `isolation.test.ts` (needs fixture rows in every tenant table; every new `:id` route needs a case in its attack matrix).
- Tenant data: only inside `withTenant(pool, tenantId, fn)` from `@1pos/database`; tenant id from the server-side session only. Every new tenant table needs: `tenant_id`, `UNIQUE(tenant_id,id)`, composite FKs, `ENABLE`+`FORCE` RLS policy, grants for `onepos_app`, and a case in the cross-tenant test suite.
- Tax: compute only via `@1pos/tax` (ADR-0008) fed by the quote path (`TaxService.quote`); VAT status/rounding live in versioned `tax_profiles`. Effective dating uses the DB clock with a 5 s skew allowance (`effectiveNowSql` / `effectiveNow()` in `apps/api/src/common/clock.ts`), never `new Date()` or bare `now()` for "in force" checks.
- Checkout: only via `SalesService.create` (ADR-0009), recorded through the private `record()` path: required Idempotency-Key + clientTransactionId, everything in one transaction. Sale header buckets = Σ lines + Σ `sale_charges`; only restaurant checks made charges (service charge ex VAT on `SERVICE_CHARGE_PAYABLE`), and table service was removed on 2026-10-25 (migration 0111): the old rows stay so those sales add up and a return gives the charge back; nothing creates new ones. A return or void of an old sale paid with a retired tender (ROOM_CHARGE, JOB_DEPOSIT) is refused (`TENDER_RETIRED`). Retail only since 2026-10-25 (migration 0112: GROCERY, SALON, PHARMACY, HYBRID removed with salons, recipes, tips and prescriptions; every business is RETAIL): migration 0113 then removed the tip and package history too, rewriting the old journal entries as if neither had existed (tip lines out of cash/clearing, package lines into Sales/Sales returns; accounts 2210/2310 deleted). Migration 0116 took the lodging/laundry accounts (1150, 2120, 2320, 2330, 4100–4120) out of the charts (deleted where unused, archived where posted to) and 2200 Service charge payable off the default chart (it stays active in charts that took charges, for their returns). Old consumption movements stay as history. An offline envelope still carrying a tip, prescriptions or a staff id is quarantined `VALIDATION_FAILED`.
- Offline sales (ADR-0015): terminals reach only `@TerminalAuth()` routes, authenticated by `SyncService.authenticate` (the tenant comes from the credential). Offline envelopes are recorded only by `SalesService.recordOffline` (re-priced as of the snapshot, ignoring price/promotion rows created after it, through `record()`, delivery row in the same tx); refusals become quarantined `terminal_transactions`, never lost. Each envelope of a batch is validated alone: one the server cannot read is quarantined `VALIDATION_FAILED`, never failing the batch. The till engine is `@1pos/pos-offline` (no React; SQLite via `SqlDriver`).
- Financial/inventory/audit tables are append-only (trigger `app_forbid_mutation`); corrections are new rows.
- Stock: insert `stock_movements` only (sorted by variant id); the costing trigger sets cost/value and balances (ADR-0012). Inbound types other than RETURN/TRANSFER_IN/COUNT must pass `unitCost`.
- Negative stock (ADR-0012 amendment): per-branch `inventory_settings`; only a counter sale (`SalesService.create`) is refused under BLOCK, by `assertStockAvailable` (locks balances through `app_lock_stock_balances`); offline sales are flagged, never refused. The costing trigger sets `below_zero` and writes the `stock.low` / `stock.below_zero` outbox events itself. Count sheets freeze on hand and post `counted − frozen` (`expected_quantity` on the count line); one OPEN sheet per branch (`SHEET_OPEN`) and no quick count of an item on it (`ITEM_ON_OPEN_SHEET`); counting needs `inventory.count` or `inventory.adjust`.
- Packs and expiry (ADR-0020): a pack and its piece are two items linked by `pack_conversions`; opening packs is a `pack_openings` document with `UNPACK_OUT`/`UNPACK_IN` movements (`recordOpening`/`openPacksForSale` in `apps/api/src/inventory/packs.service.ts`; a sale short of pieces opens packs inside `record()`). Expiry lots (`stock_lots`, `stock_lot_movements`) are written only by the trigger `app_track_stock_lots` from stock movements; services pass `expiresOn`/`lotCode` on inbound RECEIPT/ADJUSTMENT movements and `lotId` on a removal, never write lots. Packs, expiry lots and lot codes (optional) serve every shop. A sale opens packs up the chain (box → strip → piece, 3 levels) in `openPacksForSale`. Lot holds (recalls) cover the whole pack family (`app_lot_held`, `unsellableAt`); the batch trace and holds live under Inventory in the admin (API routes unchanged since ADR-0025). A held lot is never sold online at any branch (migration 0117); expired lots follow the expired-stock rule per branch (`inventory_settings.expired_stock`, no setting = ALLOW, shown as Allow; 0112 wrote BLOCK for former PHARMACY/HYBRID branches): under BLOCK they are never sold either (`assertNotExpired(…, rule)` after pack openings; the lot trigger draws held lots, and expired ones under BLOCK, last and marks `stock_lot_movements.expired`); offline sales are flagged `EXPIRED_STOCK`, never refused.
- Promotions (ADR-0021): computed only by `applyPromotions` in `@1pos/pricing`, called by `TaxService.computeCart` (counter quote/sale/exchange/offline) and by the offline engine from the snapshot, so both price alike; the result is the line's ordinary `discount` plus `sale_lines.promotion_id`. A line with SC/PWD, its own discount or an approved price is never promoted. Promotion terms are immutable (trigger): rename or end only; changing terms = end + new.
- Books: every new operational document posts one entry via `post()` (`apps/api/src/accounting/ledger.ts`) with rules from `@1pos/accounting`, in the same transaction (ADR-0013); `ledger.test.ts` compares GL to evidence. Only MANUAL entries are reversed by hand; a document's entry is corrected by its document (`CANCEL_THE_DOCUMENT`).
- Migrations that back-fill data run as the migrator under FORCE RLS: wrap the backfill in `ALTER TABLE … NO FORCE ROW LEVEL SECURITY` / `FORCE` (see 0014, 0023, 0029, 0049) for every table it reads as well as writes (e.g. `tenants` when it loops over businesses), or it silently touches no rows. Check the row counts on the dev DB after migrating. In plpgsql triggers shared by two tables, read table-specific `NEW` fields in separate IF branches.
- Account security (ADR-0016): credentials (sessions, MFA factors/recovery codes, reset tokens) have no runtime grants; reach them only via `auth_*` SECURITY DEFINER functions. Account events outside a tenant are NULL-tenant audit rows written by those functions (`auth_record_event`). MFA is enforced in `AuthGuard` for privileged members (`PRIVILEGED_PERMISSIONS`) on tenant routes only. In tests, read NULL-tenant rows / `users` / MFA tables under `SET LOCAL ROLE onepos_platform`.
- Rate limits: `@RateLimit(...rules)` with `by: 'ip' | 'account' | 'terminal'`; counters in Redis when `REDIS_URL` is set (falls back to the process if Redis is down). Integration tests count in memory: `setup-env.ts` moves `REDIS_URL` to `TEST_REDIS_URL`; Redis tests pass `REDIS_URL` + a unique `RATE_LIMIT_PREFIX`.
- Data export (ADR-0016 slice 6): the worker exports every tenant table. A new tenant table needs `GRANT SELECT ON <table> TO onepos_worker` in its migration (a column list if it has a secret column, which then goes in `EXPORT_SECRET_COLUMNS`), or an entry in `EXPORT_EXCLUDED_TABLES` with the reason; `rls-catalog.test.ts` fails otherwise. Files go through `FileStorage` (`DevFileStorage` until D1).
- Runbooks: `docs/operations/README.md` (index). Privacy pack for the DPO: `docs/compliance/privacy/`. A new table or column holding personal data needs its row in `processing-register.md` and `retention-schedule.md`. drizzle runs all pending migrations in one transaction and silently skips a file whose journal `when` is not newer than the last applied one: never hand-edit `_journal.json` or reorder files (`migrations.test.ts` guards it); procedure in `database-migrations.md`.
- Support access (ADR-0016 slice 6): a token with `sgr` is a Tilvara staff support session (read-only, re-checked every request, `auth.support` set, `membershipId` null). A route a suspended or lapsed business must still use takes `@AllowReadOnlyBusiness()` and `mutate(…, { allowReadOnlyBusiness: true })`; nothing else may, except `SalesService.recordOffline` (session 21): a sale on a snapshot stamped `business_writable` and rung within its window is recorded and audited, anything else gets `readOnlyReason()`.
- Plan features (session 21): `assertFeature` for `api_access`, `advanced_reports` (the analysis reports, via `AnalysisReportsService.read`) and `multi_entity` (a second legal entity). Everyday and statutory reports stay on every plan. Staff: `pnpm --filter @1pos/database support staff-add|staff-disable|staff-list`. Plan/status changes until billing (D6): `support subscription-show|subscription-set` (audited `subscription.changed` in the business's log, migration 0127), never hand-typed `platform_set_subscription`; webhooks stop with `api_access`.
- The outbox worker connects as `onepos_worker` (`WORKER_DATABASE_URL`); only it may call `outbox_*` / `platform_purge_expired_idempotency`. A new handler that reads more tables needs an explicit column grant in a migration (`rls-catalog.test.ts` lists what the worker may read).
- NestJS: every constructor dependency uses explicit `@Inject(Token)` — Vitest does not emit decorator metadata (SWC native binding fails on this machine, so it was removed).
- Drizzle wraps pg errors (`Failed query: …`); the Postgres error is on `err.cause`.
- User guide (session 18): admin `/help` (`apps/admin-web/src/lib/guide.ts`, copy `guide.*`) and the counter's guide (`apps/pos-desktop/src/lib/guide.ts`, ? or F1). A new admin area or counter screen gets its part or lines (and a `TOPIC_BY_PATH` entry for a new admin path); a changed button label means updating the guide line that quotes it (no test catches that). `guide.test.ts` fails on missing EN/FIL copy or orphan `guide.<area>.sN/tN` keys.
- Customers and store credit (ADR-0018): personal fields only on `customers` (audit rows name changed fields, never values); consent changes are rows in `customer_consent_events`; store credit is `customer_credit_entries` per (customer, legal entity), written with the sale or return in `record()`, posting to `CUSTOMER_STORE_CREDIT`. Store credit never becomes drawer cash: a return of a sale paid with credit gives that share back as credit to the payer (`creditShare`, trigger 0107); an exchange of a sale paid with credit is refused.
- Counter controls (ADR-0017): a price override is a `price_overrides` row approved by a second person's credentials (`AuthService.verifySecondPerson`) and consumed by `computeCart`; an exchange is `ReturnsService.record(..., {exchange})` + the new sale in one transaction (`exchangeCredit`).
- Integrations (ADR-0019): API keys are GET-only tenant sessions built in `AuthGuard` (scopes → permission codes; plan feature `api_access`); `key_hash` is never readable by the app. A new webhook topic goes in `WEBHOOK_TOPICS` (`@1pos/database`), `WEBHOOK_TOPIC_NAMES` (validation) and the admin copy; payloads carry ids, document numbers and stock figures only, never personal data or free text. Deliveries are written and settled only through the `webhook_*` definer functions (worker).
- Extensions (ADR-0026): retail is the base; an industry comes back as an extension, never as a business type. Checklist `docs/architecture/extensions.md`: manifest in `EXTENSIONS` (`@1pos/validation`), a migration inserting the `extensions` catalog row, its `permissions` rows and `plans.extensions`, its own tables (never required columns on core tables), `@RequiresExtension(code)` on its controllers (writes refused while off; reads open), `assertExtension(db, code)` inside transactions, server hooks in `apps/api/src/extensions/registry.ts`, `extension` on its admin nav item / guide area / permission group and till tab. Screens read `/me` → `activeTenant.extensions`; the snapshot carries them; offline sales are never refused for an extension. Integration tests use the test-only `test_fixture` extensions (`test/integration/fixtures/extension-fixture.ts`).
- Branding (session 39): one `tenant_branding` row per business + immutable `brand_assets` (PNG/JPEG/WebP read from the bytes in `brand-image.ts`, never SVG; logo 256 KB, background 1 MB; a replaced image is deleted in the same tx). Read through `readBranding(db)` (`apps/api/src/business/branding.ts`); receipts get `receiptBranding(...)` beside, never instead of, the legal names and notice. The colour must keep white text at 4.5:1 (`brandColorSchema`); the admin sets it on the band only (`brandVars`), whose name is the Branding name, else the business's (`band-name`, 104px from lg so the tabs fit), the till on its action colour (`applyBrandColor`). The till takes branding from its snapshot (images cached by hash in its file, `brand_images`), a browser till from `/business/branding` after sign-in. `/s/<slug>` reads only `auth_public_shop*` (opt-in `public_sign_in`). Audit rows name changed fields, never values.
- Update `docs/STATUS.md` + `docs/BACKLOG.md` + `docs/LEFTOVER.md` at the end of each session.
